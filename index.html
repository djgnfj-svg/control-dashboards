로봇 관제 대시보드

현장 로봇 18대(9종, 4개 구역)의 상태를 MQTT로 받고 이동·정지·루틴 명령을 보내는 웹 관제입니다. 3단계 권한, 로봇 호출 워치 앱, 오프라인 설치본까지 운영 중입니다. 서버 테스트 704개.

React 19ViteFastAPIpaho-mqttMQTT over WebSocketWebRTCNginxDocker ComposeKotlin · Wear OS

문제와 해결

11.4초 → 0~128ms지도 레이어를 끄는 데 화면이 11초 멈췄다

문제GPS 지도에서 경로 레이어를 끄면 11.4초, 맵 에디터에서 마커를 한 번 누를 때마다 13초씩 화면이 굳었습니다.
원인그리는 비용은 작았습니다(선 968개 0.4초). 조작할 때마다 968개를 하나씩 지도에서 떼는 루프가 8~11초를 먹고 있었습니다.
해결레이어는 처음 켤 때 한 번만 만들고 이후엔 보이기/숨기기만 바꿉니다. 에디터는 바뀐 부분만 다시 그리고, 대량 생성은 12ms 프레임 예산으로 나눴습니다.
결과마커 클릭 13.4초 → 0ms, 드래그 13.7초 → 62ms, 로딩 중 멈춤 14.2초 → 3.7초.

취소를 눌렀는데 로봇이 다시 출발했다 — 명령 ACK 추적 재설계

문제취소해도 대기열이 안 풀려 화면엔 계속 「이동 중」이 떴고, 멀쩡한 로봇에 「미배달」 경고가 뜨기도 했습니다.
원인ACK 대기 칸이 로봇당 하나라, 늦게 온 이동 ACK가 취소 명령의 추적을 지웠습니다. 로봇은 출발까지 최대 10초 뒤 ACK를 주는데 재시도 창은 7초였습니다.
해결추적을 로봇 × 명령별로 나누고, 취소·정지가 나가면 이전 명령의 재발행을 끊었습니다. ACK가 끝내 안 와도 큐를 지우지 않고 「미배달」로 사람에게 넘깁니다 — 무응답은 「못 받았다」가 아니니까요. 이동 명령만 재시도 창을 15.5초로 늘렸습니다.
결과회귀 테스트 4 → 25건. 연결 끊김·거부 응답이 조용히 사라지지 않고 경고로 드러납니다.

먼 길을 가던 로봇의 작업이 도중에 취소됐다 — 제어권 lease 모델

문제집으로 돌아가는 긴 이동 중에 제어권이 자동 만료돼 작업이 끊겼고, 탭을 닫으면 락이 남는 버그도 있었습니다.
원인클라이언트 타이머 4개(하트비트, 3분 무조작 반납, 화면 전환 감지 등)가 제각각 만료를 판정했습니다.
해결만료 판정을 서버의 순수 함수 하나로 모았습니다(연결 30초 · 활동 180초). 3초 상태 폴링이 생존 신호를 겸하고, 로봇이 움직이는 동안은 활동으로 칩니다.
결과타이머 4개 → 1개. 오래된 락 지적 2건이 구조적으로 사라졌고, 강제 회수·계정별 권한을 이 위에 올렸습니다.

빌드가 깨져도 「DEPLOY OK」 — 거짓 배포 성공 제거

문제빌드가 실패하거나 백엔드가 뜨지 않아도 배포 로그엔 성공이 찍혔습니다.
원인세 곳이 가짜 신호를 봤습니다 — 파이프 끝 로그 함수의 종료 코드(항상 0), 백엔드가 죽어도 200을 주는 정적 페이지, 서버의 compose 버전과 다른 컨테이너 이름 규칙.
해결빌드는 compose 의 실제 종료 코드로, 배포는 nginx를 거친 백엔드 헬스 체크로(최대 60초 폴링), 컨테이너는 이름 대신 라벨로 판정합니다.
결과빌드 실패와 영구 502가 FAILED로 잡힙니다. 「진짜 신호로 판정한다」가 프로젝트 규약이 됐습니다.

40건 중 6건 반증AI 멀티에이전트 코드 감사

문제한 관점으로 전체 코드를 점검하면 빠뜨리는 곳과 오탐이 섞였습니다.
해결보안 · 동시성 · 정확성 등 8개 축으로 병렬 탐지한 뒤, 발견마다 독립 에이전트가 반증을 시도하게 했습니다. 마지막에 어느 축도 안 본 곳을 훑는 단계를 더했습니다.
결과확정 25건 · 반증 6건. 스테이징이 실로봇과 같은 브로커를 공유하던 치명적 문제를 찾았습니다.

영상이 17초 늦게 왔다 — HLS에서 WebRTC로

원인같은 영상을 RTMP로 직접 받으면 약 2초, 웹 HLS는 약 17초 — 세그먼트 버퍼가 지연을 쌓고 있었습니다.
해결HLS를 빼고 WebRTC(WHEP)로 전환했습니다.

문제와 해결

3,067만 → 85만 점368MB 라이다를 브라우저에 올리기

문제로봇 라이다 원본은 30,672,451점 · 368MB라 지도와 3D 보기에 올릴 수 없었고, 로봇 좌표(UTM)와 라이다 좌표도 맞지 않았습니다.
원인원본 해상도 그대로였고, 라이다 좌표는 UTM과 축은 같지만 원점이 다른 로컬 좌표였습니다.
해결0.25m 복셀 평균으로 점을 줄이고, 주행 경로가 나무 열 사이를 지나도록 FFT 상관으로 두 좌표의 이동값을 찾았습니다.
결과852,793점 · 6.0MB. 회전을 ±1.5° 흔들어도 정합이 0.4m 안에서 유지되고, 원본과의 비율 오차는 0.29% 이내입니다.

공공데이터 인증키를 공개 사이트에 둘 수 없었다

문제브라우저에서 기상청 · 팜맵 API를 직접 부르면 인증키가 그대로 노출됩니다.
해결중계 서버를 두어 키는 서버 비밀값으로만 붙입니다. 활용 신청한 6개 경로와 허용 출처만 통과시키고, 느린 팜맵은 긴 제한시간 · 재시도를 따로 줍니다.
결과키가 공개 코드에서 빠졌습니다. 해외 CDN 구간이 간헐적으로 끊기는 걸 확인하고 국내 서버 중계로 옮겼습니다.

배포해도 옛 화면이 나왔다 — 남의 서비스워커

문제배포 후에도 사용자 브라우저엔 옛 목업이 떴고, 캐시 무효화 버전값을 올려도 소용없었습니다.
원인같은 출처 루트에 있던 다른 사이트의 서비스워커가 출처 전체를 「캐시 우선」으로 가로채고 있었습니다.
해결이 경로에만 걸리는 더 좁은 범위의 서비스워커를 등록해 루트 것을 이기게 하고, 남은 캐시를 지웠습니다. 버전값은 배포 스크립트가 자동으로 올립니다.
결과한 번 새로고침한 뒤로는 배포가 바로 반영됩니다.

15.6m로봇 경로가 필지 밖으로 밀려 보였다 — 표시값 전수 대조

문제경로 노드 53개 중 18개가 필지 밖에 찍혔고, 필지 면적도 실제보다 작게(5,690㎡ vs 5,720㎡) 나왔습니다.
원인면적은 1도당 거리를 고정값으로 쓴 탓이었습니다. 어긋남은 코드가 아니었습니다 — 위성영상과 대조하니 로봇이 맞았고, 종이 지적도를 이어 붙인 연속지적도가 밀려 있었습니다.
해결면적을 위도별 자오선 · 평행권 길이로 계산하고, 화면 수치 10개를 원본 API와 독립 계산으로 대조한 표를 남겼습니다.
결과면적이 측지 정확값과 일치하고, 나머지 9개 항목도 일치를 확인했습니다.

진짜와 가짜가 섞인 데모 — 목업 전면 제거

문제초기 데모에 가짜 농지 · 가짜 기상 수치 · 근거 없는 적합도 점수가 섞여 무엇이 진짜인지 알 수 없었습니다.
해결목업을 모두 지우고 실제 API가 붙은 것만 표시합니다. 결측값(-998.9), JSON 대신 XML로 오는 「자료 없음」, 중복 기록 같은 공공 API 함정을 처리했고, 예보 지역은 필지 주소로 정합니다.
결과「실제 데이터만 표시」가 프로젝트 원칙이 됐습니다.
