Project 01 · 채용 자동지원

공고 수집에서 제출까지 네 걸음

1 · 수집

원티드·잡코리아·사람인을 훑어 마감 표를 만든다. 백엔드·AI·로봇/관제·Python 축만 남긴다.

2 · 맞춤 이력서

마스터 이력서에서 공고와 무관한 경험을 과감히 지우고, 공고에 맞춘 PDF 를 만든다.

3 · 묻기

공고 보기 · 이력서 보기 · 내기 · 안 냄(까닭을 받는다). 모든 결정이 로그로 남는다.

4 · 지원

내가 만든 PDF 를 첨부해 제출까지. 사이트 양식을 요구하는 공고는 실패가 아니라 「직접 낼 공고」로 까닭째 분리한다.

문제 · 비용

공고 1,200건을 매번 다시 읽고 있었다

문제

원티드 한 번 훑는 데 764번 호출, 8분.

원인

게시일 필드가 없어 최신순 1,200건을 다 봐야 했고, 표에는 통과한 공고만 남으니 떨어진 공고를 매번 다시 읽었다.

해결

한 번 본 공고는 버린 까닭(직무·연봉·마감·외부링크·상시)과 함께 기억한다. 상시채용은 내용째 담아 호출 없이 되살린다. 기준이 바뀌면 그때만 다시 본다.

8분 → 5초

문제 · 판정

좋은 공고가 한 줄 꼬리표에 잘렸다

문제

Python 이 7번 나오는 정타 공고가 「병역특례 지원 가능」 한 줄 때문에 탈락. 반대로 후보 100건 중 36건은 경력 미달이었다.

원인

제목만으로 붙이고, 학위·병역 같은 부수 조건으로 자르고, 한 사이트엔 경력 게이트가 없었다.

해결

제목은 후보를 좁히는 그물, 붙일지는 본문이 정한다. 주요업무·자격요건에서 Python 신호와 경쟁 스택을 세어 경쟁 스택이 2 이상 많을 때만 뺀다. 탈락 사유는 스택·응답률 둘로 묶고, 나머지는 꼬리표로만 단다. 경력 하한 게이트를 세 사이트에 똑같이.

결과

기준 정본(CRITERIA.md) 하나를 코드가 그대로 실행한다.

Project 02 · 이력서 하네스

LLM 이 쓴 이력서를 LLM 이 세어서 검사한다

문제

「통과」 한 마디로 끝나는 자기 검토. 과장·공고 베끼기·지원 동기 같은 빈말이 새어 나왔다.

규칙 8갈래

길이가 아니라 적합도 · 지어내지 않기 · 한 줄에 도메인·문제·해결·성과 · 공고는 파악하되 베끼지 않기 …

계수표 13줄셀 수 있는 것은 센다 — 「통과」로 갈음 못 한다

분리

이력서 일은 별도 프로세스(claude -p)가 제 폴더에서 한다. 메인 세션은 권한(deny)으로 그 폴더를 못 읽어, 두 컨텍스트가 섞이지 않는다.

설계 · 안전

자동화하되, 실수로 지원서가 나가진 않게

위험

새 사이트를 붙이며 시험하는 중에 진짜 지원서가 나갈 수 있다.

제출 잠금

허용 목록에 적힌 사이트만 실제 제출. 나머지는 폼까지 채우고 멈춘다. 잠금은 Python·Node 양쪽에 걸려 스크립트를 직접 불러도 막히고, 푸는 건 사람 손으로만.

사람이 고른다

저절로 시작하는 길은 없다. 판정기는 그물일 뿐, 낼 공고는 사람이 북마크로 확정한다. 「내기」는 두 번 눌러야 간다.

결과

결정 146건(물음·안 냄·막힘)이 모두 로그로 남아 나중에 기준을 고칠 근거가 된다.

Project 04 · 브라우저 에이전트

구글 로그인 팝업이 에이전트 밖으로 새어 나갔다

문제

구글 버튼을 눌러도 「무반응」. 에이전트는 사람에게 직접 로그인해 달라고 넘겼다.

원인

로그인 팝업이 에이전트가 다룰 수 없는 별도 창으로 떴다. 잡코리아는 브라우저 자체 로그인(FedCM)까지 끼어들었다.

해결

클릭 직전에 페이지의 window.open 을 새 탭 열기로 바꿔, 팝업을 에이전트의 탭 안으로 받는다. 사이트별 로그인 판별식과 단계를 절차서로 고정했다.

결과

세 사이트 모두 사람 손 0 으로 붙는다. X 가 나오면 그대로 믿지 않고, 어느 단계에서 어긋났는지 적어 한 번 더 돌린다.

실험 · 판정 모델 JEV

메일 판정을 LLM 대신 판정 전용 모델에 맡기면?

실험

Claude 에이전트가 지운 메일 146통을 TypeSafe JEV(글 대신 선택지와 확신도를 돌려주는 System One 모델)에 다시 판정시켰다. 선택지는 메일 규칙의 삭제 사유 다섯 + 「남김」.

91% · 사유 88%휴지통 판정 133/146 · 사유까지 78/89 일치

$0.004146통 전체 · 한 통 중앙값 0.6초

어긋난 13통

AI 뉴스레터 3통은 규칙이 「AI 관련은 남긴다」인데 Claude 가 지웠고 JEV 가 맞게 남겼다. 나머지는 개발 뉴스레터·서비스 공지처럼 규칙의 경계에 선 메일이었다.

확신도가 곧 라우팅 신호

일치한 판정의 확신도 평균 0.92, 어긋난 판정 0.60. 확신도 0.7 이상만 JEV 가 처리하면 121통(83%)을 96.7% 일치로 끝내고, 나머지 25통만 Claude 에게 넘기면 된다.

프로토타입 · LLM 로봇 조작

「1번 창고A 갔다가 조립라인으로」를 관제 명령으로

무엇

현업 관제와 같은 MQTT 바이너리 프로토콜(MOVE_POS · STOP · RUN_ROUTINE · 상태 DATA3)에 LLM 자연어 조작을 붙였다. 모의 로봇 3대에서 동작을 확인했다. 현장 IP·도면은 싣지 않았다.

설계

LLM 은 장소 이름만 고르고 좌표를 모른다. 좌표 · 연결 · 배터리 확인과 명령 발행은 관제 층 코드가 하고, 명령 뒤 3초 안에 텔레메트리가 안 바뀌면 성공이 아니라 「미배달」.
